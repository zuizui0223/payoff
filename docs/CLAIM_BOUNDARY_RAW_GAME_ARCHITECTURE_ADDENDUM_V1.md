# Claim-boundary addendum: raw / game / architecture separation v1

This addendum is stricter than a prose warning: the repository now has separate receipt types and a machine promotion gate.

## Allowed claims by lane

### Lane R

If raw reconstruction passes:

> The declared public archive, schema and transformations were reproducibly reconstructed.

Do **not** append:

> therefore frequency dependence is present.

Do **not** append:

> therefore the alternatives are PAYOFF shared and differentiated architectures.

### Lane G

If generic game validation passes:

> The declared neutral strategy pair exhibits the recovered frequency-game pattern on the stated outcome scale and time horizon.

Do **not** relabel the neutral strategies as PAYOFF S/D architectures unless Lane A independently passes and the pair-alignment gate passes.

### Lane A

If architecture mapping passes:

> The declared empirical alternatives instantiate the registered integrated/shared versus differentiated/released architecture contrast on the stated strategic unit.

Do **not** infer frequency-dependent fitness, `eta`, coexistence or dominance from Lane A alone.

## Architecture-specific promotion

The following claim is licensed only by the explicit intersection gate:

> Frequency-dependent relative fitness has been identified for a declared PAYOFF integrated/shared versus differentiated/released architecture pair.

Required:

```text
Lane G certified
Lane A certified
same system
same comparison
same strategic unit
explicit pair alignment
```

No amount of raw reproducibility substitutes for any of these semantic conditions.
