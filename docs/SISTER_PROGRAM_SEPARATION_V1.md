# PAYOFF vs. sister-program validation — separation contract v1

## Purpose

PAYOFF is a cross-repository population-game extension. It must not replace the independent theory -> causal validation -> generality programmes owned by SCH, BALANCE, and BITA.

## Ownership rule

PAYOFF may consume frozen sister-repository quantities such as:

```text
SCH      L / shared-conflict geometry
BALANCE  direct worldline ordering and middle-world state
BITA     R, s, K or architecture-margin estimates when independently identified
```

PAYOFF then asks a different question:

```text
what happens when alternative heritable architectures interact through population frequency,
invasion, coexistence, coordination or switching dynamics?
```

The frequency-feedback parameter `eta` and related invasion surfaces are PAYOFF-owned quantities.

## Non-substitution rule

A theorem, simulation, or empirical result in PAYOFF cannot be used to promote any of the following sister-repository claims:

```text
SCH causal shared-coordinate conflict
BALANCE direct sandwiched-world occupancy
BITA causal dimensional release / preferential loading / mechanism identification
```

Those claims must pass their own repository-specific empirical gates.

Likewise, a positive sister-repository result does not identify PAYOFF frequency dependence. `eta != 0` requires an independent architecture-frequency experiment or an otherwise justified population-frequency design.

## Independent sister pipelines

The programme therefore contains four logically distinct layers:

```text
SCH
  theory -> causal shared-coordinate conflict -> cross-system generality

BALANCE
  theory -> direct middle-world / persistence tests -> cross-system generality

BITA
  theory -> causal dimensional release / mechanism -> cross-system generality

PAYOFF
  static sister quantities -> population game -> invasion/coexistence/coordination tests
```

## Claim ceiling

PAYOFF is a meta-theory of architecture-state competition. It does not prove that any empirical system reviewed in the sister repositories evolved through the modeled game, and it does not count as a replication of any sister chapter's defining causal signature.
